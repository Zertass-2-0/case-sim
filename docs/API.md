# CaseSim API reference

Base URL (local): `http://localhost:3000` (the port is `APP_PORT` from `.env`). All endpoints live under `/api`, requests and responses are JSON.

## Conventions

**Authentication.** Everything except `/api/health`, `/api/auth/register` and `/api/auth/login` needs the header

```
Authorization: Bearer <token>
```

The token is returned by register/login and is valid for 7 days. Endpoints marked **admin** also require `is_admin = true`.

**Errors.** Every error has the same shape: `{ "error": "human readable message" }`.

| Status | Meaning |
|---|---|
| 400 | Bad request: invalid or missing fields |
| 401 | No token, expired token, or wrong login |
| 402 | Not enough coins |
| 403 | Logged in, but not an admin |
| 404 | The thing with this id does not exist |
| 409 | Conflict: nick taken, or the row is still used by other rows |
| 500 | Unexpected server error |

**Numbers.** Floats (`float`, `min_float`, `max_float`) and `balance` are returned as **strings** (e.g. `"0.12345678"`): PostgreSQL `NUMERIC`/`BIGINT` is exact and JSON numbers are not.

## Health

### `GET /api/health`
Checks that the backend is up and can query the database. No auth.
`200` → `{ "status": "ok" }`

## Auth

### `POST /api/auth/register`
Body: `{ "nick": "player_1", "password": "secret123" }`. Nick: 3-20 letters/digits/underscore (unique, case-insensitive). Password: 6-72 characters.
`201` → `{ "token": "...", "user": { "id": 3, "nick": "player_1", "balance": "1000", "is_admin": false } }`
Errors: `400` invalid nick/password, `409` nick already taken.

### `POST /api/auth/login`
Body: `{ "nick": "player_1", "password": "secret123" }`
`200` → same shape as register. Error: `401` wrong nick or password.

### `GET /api/me`
`200` → `{ "id": 3, "nick": "player_1", "balance": "1000", "is_admin": false }`

## Skins: full CRUD (the resource for the Midterm)

A skin is a weapon design that can drop from cases.

```json
{
  "id": "skin-39c96dc59741",
  "name": "AK-47 | Vulcan",
  "image_url": "https://example.com/vulcan.png",
  "min_float": "0.00000000",
  "max_float": "1.00000000",
  "rarity": "rarity_rare_weapon",
  "rarity_name": "Mil-Spec",
  "rarity_tier": 1
}
```

Rarity codes: `rarity_rare_weapon` (tier 1), `rarity_mythical_weapon` (2), `rarity_legendary_weapon` (3), `rarity_ancient_weapon` (4).

### `GET /api/skins` : list
Query parameters (all optional): `rarity` (rarity code), `q` (part of the name, case-insensitive), `limit` (1-100, default 20), `offset` (default 0).
`200` → `{ "total": 69, "limit": 20, "offset": 0, "items": [ <skin>, ... ] }`
`total` is the number of skins matching the filters, ignoring limit/offset. Error: `400` invalid limit/offset.

### `GET /api/skins/:id` : get by id
`200` → `<skin>`. Error: `404` unknown id.

### `POST /api/skins` : create (**admin**)
Body (all fields required):
```json
{ "name": "Test | Skin", "rarity": "rarity_rare_weapon", "image_url": "https://example.com/x.png", "min_float": 0, "max_float": 0.5 }
```
The id is generated by the server.
`201` + header `Location: /api/skins/<id>` → `<skin>`.
Errors: `400` validation (name 1-100 chars, known rarity code, http(s) URL, floats in 0..1 and min ≤ max), `403` not admin.

### `PUT /api/skins/:id` : update (**admin**)
Body: the same full object as for create (PUT replaces all editable fields).
`200` → updated `<skin>`. Errors: `400`, `403`, `404`.
Items that players already own keep their float; only the skin template changes.

### `DELETE /api/skins/:id` : delete (**admin**)
`204` (empty body). Errors: `403`, `404`, `409` if some player owns an item of this skin.

## Cases and inventory

### `GET /api/cases`
`200` → `[ { "id": 1, "name": "Huntsman Weapon Case", "image_url": "...", "price": 100, "owned": 0, "skin_count": 20 }, ... ]` (`owned` = unopened cases this player holds).

### `GET /api/cases/:id`
`200` → the case plus `skins: [ { id, name, image_url, min_float, max_float, rarity_name, color, tier, drop_weight, chance }, ... ]` where `chance` is the drop probability (0..1). Error: `404`.

### `POST /api/cases/:id/open`
Opens a case: uses an owned one first, otherwise pays its price. No body.
`201` → `{ "item": { id, skin_id, name, image_url, rarity, rarity_tier, color, float, wear, special, price, source, acquired_at }, "paid": 100, "free_open": false, "balance": "900" }`
Errors: `402` not enough coins, `404`.

### `GET /api/inventory`
`200` → array of items (same item shape as above), newest first.

### `POST /api/inventory/sell`
Body: `{ "ids": [15, 16] }` (inventory item ids, 1-100, no duplicates, must be yours).
`200` → `{ "sold": 2, "earned": 140, "balance": "1040" }`. Errors: `400`, `404` item not in your inventory.

### `GET /api/transactions`
`200` → last 30 balance changes: `[ { "id", "kind", "amount", "note", "created_at" } ]`.

### `GET /api/leaderboard`
`200` → `{ "cleanest": [ { float, name, image_url, color, nick } ], "richest": [ { nick, balance, items } ] }` (top 10 each).

## Trade-up contracts

### `POST /api/contracts/preview`
Body: `{ "ids": [10 item ids of the same rarity] }`. Shows possible results without changing anything.
`200` → `[ { skin_id, name, image_url, rarity, color, float, wear, special, price, chance } ]`
Errors: `400` (not exactly 10, mixed rarity, highest rarity), `404`.

### `POST /api/contracts`
Same body. Destroys the 10 items and gives 1 item of the next rarity (float = average of the inputs).
`201` → `{ "item": { ... } }`. Same errors.

## Admin (all require **admin**)

### `GET /api/admin/users`
`200` → `[ { id, nick, balance, is_admin, items, cases } ]`

### `GET /api/admin/skins`
`200` → `[ { id, name, min_float, max_float, rarity } ]` (short list used by the admin panel; for full CRUD use `/api/skins`).

### `POST /api/admin/money`
Body: `{ "nick": "player_1", "amount": 500 }` (negative takes coins, non-zero integer).
`200` → `{ "nick", "balance" }`. Errors: `400`, `404` unknown nick, `400` if the balance would go below 0.

### `POST /api/admin/case`
Body: `{ "nick": "player_1", "caseId": 1, "qty": 2 }` (qty 1-1000).
`201` → `{ "nick", "case", "owned" }`. Errors: `400`, `404`.

### `POST /api/admin/skin`
Body: `{ "nick": "player_1", "skinId": "skin-...", "float": 0.5 }` (`float` optional: random inside the skin's range if omitted).
`201` → `{ "nick", "skin", "float" }`. Errors: `400` float outside the skin's range, `404`.

Import `postman/CaseSim.postman_collection.json` and `postman/CaseSim.postman_environment.json`, select the environment, put `ADMIN_PASSWORD` from your `.env` into the `adminPassword` variable, then run the collection (Runner) top to bottom. Every request has tests; the folder "2. Skins (CRUD)" is the Midterm resource.
